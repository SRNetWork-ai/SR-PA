# API پنل SR-UI

همان APIای که خود رابط وب پنل با آن کار می‌کند. «API عمومی» جداگانه و محدودشده‌ای
وجود ندارد: هر کاری که پنل می‌تواند انجام دهد، یک برنامه هم می‌تواند — با همان
بررسی‌های دسترسی.

دو راه احراز هویت:

| | برای | اعتبارنامه |
|---|---|---|
| نشست (Session) | رابط وب | کوکی امضاشده، ۶ ساعته |
| توکن API | اسکریپت، سیستم فروش، مانیتورینگ، پنل دیگر | توکن Bearer |

---

## ۱. مهم‌ترین نکته درباره توکن‌ها

**توکن یک مجموعه دسترسی مستقل نیست؛ یک «کپی محدودشده» از همان ادمینی است که آن را
ساخته، و این محدودسازی در هر درخواست از نو محاسبه می‌شود.**

هر قاعده دیگری در این سند از همین یک جمله بیرون می‌آید:

- دسترسی مؤثر توکن = «دسترسی فعلی مالک» ∩ «اسکوپ توکن». نه دسترسی‌ای که مالک در
  لحظه ساخت توکن داشته.
- دسترسی یک ادمین را کم کنید، **توکن‌هایش همان لحظه محدود می‌شوند** — بدون چرخش
  توکن، بدون فهرست پاکسازی، و بدون اعتبارنامه‌ای که دسترسی ازدست‌رفته را نگه داشته باشد.
- ادمین را غیرفعال یا حذف کنید، **توکن‌هایش از کار می‌افتند**. اینجا اعتبارنامه‌ای که
  از مسئولش عمر بیشتری داشته باشد وجود ندارد.
- سوپرادمین **ارث نمی‌رسد**. باید صریحاً هنگام ساخت درخواست شود (`superAdmin: true`)
  و فقط یک سوپرادمین می‌تواند آن را بدهد. بدون آن، توکن مالک پنل هم دقیقاً به همان
  اسکوپ‌های نوشته‌شده محدود است.
- **حساب نمایندگی (reseller) اصلاً نمی‌تواند توکن بسازد.** دسترسی نماینده از نقشش
  مشتق می‌شود نه از ماسک ذخیره‌شده؛ پس اسکوپ روی چنین توکنی ذخیره و نمایش داده می‌شد
  ولی هیچ چیزی را محدود نمی‌کرد. محدودیتی که قابل اعمال نیست، پیشنهاد نمی‌شود — رد می‌شود.

پنل فقط هش SHA-256 توکن را نگه می‌دارد به‌همراه یک نشانه ۴+۴ کاراکتری
(`a1b2..9f8e`) برای تشخیص توکن‌ها از هم. **خود توکن فقط یک‌بار نشان داده می‌شود**،
در همان پاسخی که آن را می‌سازد. بازیابی‌شدنی نیست؛ فقط جایگزین‌شدنی است.

## ۲. فرستادن توکن

همه مسیرهای API **زیر مسیر مخفی پنل** هستند؛ همان بخش تصادفی آدرسی که با آن وارد
می‌شوید. توکن به‌تنهایی برای پیدا کردن آن‌ها کافی نیست.

```sh
SCHEME=https                      # یا http، اگر هنوز TLS ندارید
HOST=panel.example.com:2053
BASE=$SCHEME://$HOST/yourSecretPath
TOKEN=همان-توکنی-که-یک-بار-دیدید

curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/panel/api/nodes/list"
```

سه روش ارسال، به همین ترتیب:

1. `Authorization: Bearer <token>` — **همین را استفاده کنید.**
2. `X-API-Token: <token>` — برای کلاینت‌هایی که `Authorization` را خودشان اشغال می‌کنند.
3. `?apiToken=<token>` — امتیازی برای ابزارهایی که نمی‌توانند هدر بفرستند. در لاگ
   دسترسی، لاگ پروکسی و تاریخ شل باقی می‌ماند. تا جای ممکن استفاده نکنید.

### خواندن پاسخ

همه مسیرها یک پوشش یکسان دارند:

```json
{ "success": true, "msg": "", "obj": { } }
```

| کد | معنی |
|---|---|
| `200` + `success: true` | انجام شد |
| `200` + `success: false` | فهمیده شد و رد شد — معمولاً دسترسی‌ای که توکن ندارد. `msg` می‌گوید کدام. |
| `401` | خودِ توکن رد شد: ناشناس، غیرفعال، منقضی، یا ادمینش حذف شده. `msg` می‌گوید کدام. |
| `404` | **هیچ اعتبارنامه‌ای فرستاده نشده.** پنل وجود APIاش را از درخواست بی‌هویت پنهان می‌کند. اگر جای ۴۰۱ کد ۴۰۴ گرفتید، تقریباً همیشه یعنی هدر شما نرسیده. |

## ۳. اسکوپ‌ها

هر اسکوپ یکی از همان اسلاگ‌های دسترسی پنل است — همان فهرستی که صفحه **ادمین‌ها**
ویرایش می‌کند. واژگان دومی برای API ساخته نشده.

| اسلاگ | چه می‌دهد |
|---|---|
| `accessInbounds` | خواندن اینباندها، کلاینت‌ها، دستگاه‌ها و اطلاعات آدرس |
| `createInbound` / `editInbound` / `deleteInbound` | چرخه عمر اینباند |
| `createClient` / `editClient` / `deleteClient` | چرخه عمر اکانت |
| `bulkOperation` | مسیرهای عملیات گروهی |
| `accessCoreSettings` | تنظیمات هسته |
| `accessXraySettings` | کانفیگ Xray، روتینگ، اوتباند، جیو سفارشی |
| `accessPanelSettings` | تنظیمات پنل، **و صفحه نودها** |
| `manageResellers` | زیرسیستم نمایندگی |
| `accessOverview` / `manageOverview` | صفحه وضعیت سرور، و عمل‌کردن روی آن |

فهرست زنده را بگیرید و در کد ننویسید:

```sh
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/panel/api/tokens/scopes"
```

بعضی مسیرها به‌جای اسلاگ، **سوپرادمین** می‌خواهند: ساخت و حذف نود، صدور/ورود دیتابیس،
آپدیت پنل، سرویس systemd. برای آن‌ها باید توکن با `superAdmin: true` ساخته شود — کم،
و همیشه با تاریخ انقضا.

## ۴. مدیریت توکن‌ها

این مسیرها **فقط سوپرادمین** هستند و **برای درخواست‌هایی که خودشان با توکن احراز
شده‌اند رد می‌شوند** — حتی اگر آن توکن سوپرادمین باشد. اعتبارنامه‌ای که بتواند
اعتبارنامه بسازد، با یک درخواست از محدودیت خودش فرار می‌کند؛ پس ساختن توکن ورود
واقعی به پنل می‌خواهد.

| مسیر | متد | کار |
|---|---|---|
| `/panel/api/tokens/list` | GET, POST | همه توکن‌ها: نام، نشانه، مالک، اسکوپ، انقضا، آخرین استفاده |
| `/panel/api/tokens/scopes` | GET | واژگان اسلاگ‌ها |
| `/panel/api/tokens/mint` | POST | ساخت توکن، نمایش یک‌باره |
| `/panel/api/tokens/enable/:id` | POST | `{"enable": false}` — خاموش کردن، با حفظ سابقه |
| `/panel/api/tokens/del/:id` | POST | حذف همیشگی |

### ساخت توکن

```json
{
  "name": "billing sync",
  "scopes": ["accessInbounds", "createClient", "editClient"],
  "superAdmin": false,
  "ttlDays": 90
}
```

- `name` الزامی است. یک سال بعد، همین است که تصمیم می‌گیرید لغو کردنش چه چیزی را
  می‌شکند.
- `ttlDays` اگر نباشد یا `0` باشد یعنی **هرگز منقضی نمی‌شود**. مجاز است، چون بعضی
  یکپارچه‌سازی‌ها واقعاً از هر تاریخی که انتخاب کنید عمر بیشتری دارند — ولی انقضا بهتر است.
- مالک توکن **همان ادمینی است که درخواست را می‌فرستد**. فیلدی برای انتخاب شخص دیگر
  وجود ندارد: آن می‌شد مسیری برای ساختن اعتبارنامه به‌نام دیگران، و رد ردیابی اشتباه
  را نشان می‌داد.

### لغو توکن

هنگام حادثه، `enable/:id` با `{"enable": false}` را ترجیح دهید. حذف توکن، سابقه آخرین
استفاده و آدرس آن را هم حذف می‌کند — یعنی دقیقاً همان شاهدی که برای فهمیدن «این توکن
لو رفته به چه چیزی دست زده» لازم دارید. بعد از بررسی حذفش کنید.

هر ردیف `lastUsedAt` و `lastUsedFrom` دارد. این‌ها حداکثر یک‌بار در دقیقه نوشته می‌شوند:
وگرنه یک مانیتور که هر ۵ ثانیه درخواست می‌زند، در هر درخواست روی دیتابیس مشترک پنل
می‌نوشت؛ و یک دقیقه خطا در یک ستون ردیابی بسیار کم‌ارزش‌تر از آن است.

## ۵. نقشه مسیرها

همه مسیرها نسبت به `$BASE` هستند.

### نودها — `accessPanelSettings`، تغییرات نیاز به سوپرادمین

| مسیر | متد | کار |
|---|---|---|
| `/panel/api/nodes/list` | GET, POST | وضعیت کل فلیت: نسخه ایجنت و هسته، بار، ترافیک، هم‌گامی، آخرین خطا |
| `/panel/api/nodes/locations` | GET | نودها گروه‌بندی‌شده بر اساس کشور و شهر، برای مولتی‌لوکیشن |
| `/panel/api/nodes/inbounds/:id` | GET | اینباندهایی که نود سرو می‌کند |
| `/panel/api/nodes/preview/:id` | GET, POST | دقیقاً همان کانفیگ Xray که پنل به این نود می‌دهد، با هشش. فقط‌خواندنی، و سریع‌ترین راه پاسخ به «چرا این نود این را سرو می‌کند» |
| `/panel/api/nodes/save` | POST | ساخت یا ویرایش نود |
| `/panel/api/nodes/inbounds/:id` | POST | تخصیص اینباند به نود |
| `/panel/api/nodes/token/:id` | POST | ساخت توکن ثبت‌نام ۳۰ دقیقه‌ای برای ایجنت |
| `/panel/api/nodes/enable/:id` | POST | فعال/غیرفعال کردن نود |
| `/panel/api/nodes/del/:id` | POST | حذف نود |

خود زیرسیستم در [nodes-and-relay-fa.md](nodes-and-relay-fa.md) توضیح داده شده.

### اکانت‌ها و اینباندها — خواندن با `accessInbounds`

| مسیر | کار |
|---|---|
| `/panel/api/inbounds/...` | تمام سطح اینباند و کلاینت که صفحه اینباندها استفاده می‌کند |
| `/panel/api/clients/...` | نمای اکانت‌محور صفحه کلاینت‌ها |
| `/panel/api/devices/list/:email` | دستگاه‌های دیده‌شده یک اکانت — علاوه بر اسکوپ، محدود به اکانت‌های خود فراخوان |
| `/panel/api/ipintel/resolve` | شناسایی آدرس مبدأ: شبکه، اپراتور، کشور |

جزئیات در [ip-and-device-intelligence.md](ip-and-device-intelligence.md).

### سرور و هسته

| مسیر | دسترسی |
|---|---|

| `/panel/api/backuptotgbot` | `manageOverview` — **کل دیتابیس** را، شامل هش رمزها، به چت تلگرام می‌فرستد |

## ۶. آنچه توکن API نیست: کانال ایجنت نود

مسیرهای `POST <base>/node/enroll`، `POST <base>/node/heartbeat`،
`GET <base>/node/config` و `POST <base>/node/traffic` کانال خود ایجنت‌های نود هستند.
بیرون از `/panel/api` قرار دارند و با **توکن نود** کار می‌کنند که برای هر نود جداگانه
از `nodes/token/:id` گرفته می‌شود.

توکن نود هویت **یک ماشین** است و فقط به همان چهار مسیر می‌رسد. توکن API **به نمایندگی
یک ادمین** عمل می‌کند. این دو جای هم استفاده نمی‌شوند.

## ۷. توصیه‌های عملی

- **برای هر یکپارچه‌سازی یک توکن جدا**، با نام همان سرویس. توکن مشترک را نمی‌توان بدون
  قطعی‌ای که شکلش قابل پیش‌بینی نیست لغو کرد.
- **کوچک‌ترین اسکوپی که کار می‌کند** را بدهید. یک سیستم فروش معمولاً به
  `accessInbounds` + `createClient` + `editClient` و نه بیشتر نیاز دارد.
- **مالک توکن را ادمینی بگذارید که واقعاً باید آن دسترسی را داشته باشد**، نه حساب
  سوپرادمین. اشتراک ماسک‌ها تورِ ایمنی است؛ از ابتدا بازش نکنید.
- روی هر چیزی که می‌توانید بچرخانید `ttlDays` بگذارید.
- توکن در هدر از شبکه عبور می‌کند. قبل از ساختن هر توکن، TLS را روی پنل بیاورید — روی
  HTTP ساده، توکن برای هر واسطه‌ای خواناست.
- کد `404` یعنی هیچ اعتبارنامه‌ای نرسیده. قبل از شک به توکن، نام هدر را بررسی کنید.
