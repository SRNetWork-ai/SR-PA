# SR-UI

**پنل مدیریت چندپروتکلی VPN** — Xray به‌علاوه سرویس‌های بومی VPN، نود و رله برای مولتی‌لوکیشن،
یک اکانت روی چندین اینباند، و حساب‌داری دقیق برای هر اکانت.

[English](README.md) · **فارسی**

</div>

> SR-UI یک فورک اختصاصی از `vpn-ui` است (که خودش بر پایهٔ 3X-UI ساخته شده) با تم، نام و قابلیت‌های جداگانه. مجوز: GPL-3.0.

## نصب سریع

روی سرور و با کاربر `root`:

```bash
bash <(curl -fsSL raw.githubusercontent.com/SRNetWork-ai/SR-PA/main/scripts/sr-ui-install.sh)
```

بدون هیچ پرسشی (پورت، نام کاربری و رمز خودکار ساخته می‌شوند):

```bash
bash <(curl -fsSL raw.githubusercontent.com/SRNetWork-ai/SR-PA/main/scripts/sr-ui-install.sh) -y
```

اگر می‌خواهید **قبل از هر تغییری** ببینید دقیقاً چه کار می‌کند، `--dry-run` را اضافه کنید.

هستهٔ Xray و دادهٔ جیو داخل باینری ریلیز جاسازی شده‌اند، پس نصب تازه از همان لحظهٔ اول
هستهٔ سالم دارد.

> اگر `curl` شما آدرس بدون اسکیم را قبول نکرد، `https://` را به ابتدای آن اضافه کنید.

اگر روی یک **فورک خصوصی** کار می‌کنید، اینستالر برای دیدن ریلیز به توکن نیاز دارد: یا
`GITHUB_TOKEN` را در محیط بگذارید یا `--token <TOK>` بدهید.

### گزینه‌های اینستالر

| گزینه | کار |
| --- | --- |
| `-y, --yes` | بدون پرسش؛ هرچه ندادید ساخته می‌شود |
| `--port N` | پورت پنل (پیش‌فرض: یک پورت آزاد تصادفی) |
| `--username U` / `--password P` | مشخصات ورود |
| `--path P` | مسیر پایهٔ وب |
| `--version TAG` | نصب یک نسخهٔ مشخص |
| `--source` | بیلد از سورس، وقتی فایل آماده برای معماری شما نیست |
| `--swap` | ساخت swap موقت برای بیلد روی سرور کم‌رم |
| `--token TOK` | توکن گیت‌هاب (برای فورک خصوصی) |
| `--no-firewall` | دست نزدن به ufw / firewalld |
| `--uninstall` | حذف سرویس، نگه داشتن دیتابیس |
| `--purge` | همراه `--uninstall`: حذف داده‌ها هم |

### اینستالر چه چیزهایی را خودش تشخیص می‌دهد

- **توزیع لینوکس** (Debian/Ubuntu، RHEL/Alma/Rocky/Fedora، Arch، SUSE) و نصب پیش‌نیازها
- **معماری CPU** و انتخاب فایل مناسب؛ اگر فایل آماده‌ای نبود، خودش از سورس بیلد می‌کند
- **یک پورت آزاد** (به‌جای پورت ثابتی که ممکن است اشغال باشد)
- **پنل‌های نصب‌شدهٔ قبلی** (`vpn-ui`، `x-ui`، `sr-ui`) و هشدار پیش از دست زدن به آن‌ها
- **کمبود حافظه** هنگام بیلد، و ساخت swap موقت با `--swap`
- **checksum**؛ و اگر ریلیز آن را منتشر نکرده باشد، صریح می‌گوید که فایل تأیید **نشده** است

هر چیزی که نتواند مطمئن شود، گزارش می‌دهد؛ فرض نمی‌گیرد. کل کارهای تغییردهنده هم داخل یک تابع است که فقط در خط آخر صدا زده می‌شود، تا اسکریپت نیمه‌دانلودشده نتواند نصب نیمه‌کاره بسازد.

## افزودن نود (مولتی‌لوکیشن)

در پنل، صفحهٔ **نودها**: نود را بسازید، اینباندهایش را تخصیص دهید و یک توکن ثبت‌نام بگیرید.
بعد، **روی خود نود**:

```bash
bash <(curl -fsSL raw.githubusercontent.com/SRNetWork-ai/SR-PA/main/scripts/sr-node-install.sh) --url PANEL_URL --token TOKEN
```

ایجنت خودش را ثبت می‌کند، کانفیگ را از مستر می‌گیرد، هسته را بالا می‌آورد و مصرف هر اکانت را
به پنل گزارش می‌دهد، پس سهمیه و انقضا همان‌جایی اعمال می‌شود که اکانت زندگی می‌کند.
یک نود می‌تواند ترافیک را مستقیم بدهد یا از درون یک نود دیگر رله کند.

جزئیات کامل: [`docs/nodes-and-relay-fa.md`](docs/nodes-and-relay-fa.md)

## مهاجرت از vpn-ui

اگر از قبل `vpn-ui` روی سرور دارید و می‌خواهید با نام SR-UI بالا بیاید:

```bash
sudo bash scripts/srui-server-migrate.sh --dry-run   # فقط گزارش، بدون تغییر
sudo bash scripts/srui-server-migrate.sh
```

برای ریبرند سورس (تم، نام، لوگو) پیش از بیلد:

```bash
bash scripts/brand-sr-ui.sh --check   # بررسی
bash scripts/brand-sr-ui.sh
```

## محدودیت IP و دستگاه

پنل دیگر «آدرس IP» را با «دستگاه» یکی نمی‌گیرد:

- روی گیت‌وی ای **SSH**، هویت دستگاه از روی بنر کلاینت به‌علاوهٔ رنج آدرس (`/24` برای IPv4 و `/64` برای IPv6) ساخته می‌شود. یعنی گوشی‌ای که روی سیم‌کارت IP عوض می‌کند دیگر «دستگاه دوم» حساب نمی‌شود، ولی لپ‌تاپ و گوشیِ پشت یک مودم دو دستگاه شمرده می‌شوند.
- برای هر آدرس، اپراتور (همراه اول، ایرانسل، رایتل، شاتل، مخابرات و…)، نوع شبکه (موبایل / ثابت / دیتاسنتر) و کشور تشخیص داده می‌شود.
- دستگاه‌های هر اکانت در دیتابیس ثبت می‌شوند و از طریق API قابل دیدن و پاک کردن‌اند.

جزئیات: [`docs/ip-and-device-intelligence.md`](docs/ip-and-device-intelligence.md)

## API

همان APIای که خود پنل با آن کار می‌کند: اینباند، اکانت، ترافیک، نود، تنظیمات و عملیات سرور.
دو راه احراز هویت دارد: کوکی نشست برای رابط وب، و **توکن با اسکوپ** برای اسکریپت و سیستم فروش.

توکن یک مجموعه دسترسی مستقل نیست؛ **کپی محدودشدهٔ همان ادمینی است که ساختهش**، و این
محدودسازی در هر درخواست از نو محاسبه می‌شود: دسترسی یک ادمین را کم کنید، توکن‌هایش همان
لحظه محدود می‌شوند، و اگر ادمین غیرفعال یا حذف شود توکن‌هایش از کار می‌افتند.

جزئیات، اسکوپ‌ها و نقشهٔ مسیرها: [`docs/api-fa.md`](docs/api-fa.md)

## وضعیت فعلی، بدون تعارف

- شمارش بر اساس **دستگاه** فعلاً فقط روی SSH اعمال می‌شود؛ پروتکل‌های Xray هنوز بر اساس **آدرس** محدود می‌شوند و رجیستری آنجا فقط گزارش می‌دهد.
- بنر کلاینت قابل جعل است؛ فقط برای شمارش و برچسب استفاده می‌شود، هیچ‌جا برای احراز هویت.
- محدودیت IP و دستگاه هنوز صفحهٔ UI ندارد؛ داده‌ها از API در دسترس‌اند.
- زیرسیستم **نود / رله** ساخته شده است (صفحهٔ نودها، ایجنت، همگام‌سازی کانفیگ، زنجیرهٔ رله، گزارش ترافیک)؛ انتخاب میزبان اشتراک به تفکیک نود در دست کار است.
- توکن API با سطح دسترسی اضافه شده است؛ صفحهٔ مدیریت توکن در رابط وب هنوز ساخته نشده و فعلاً از خود API ساخته می‌شود.
